# stage31 可携带方案摘要

> 2026-11-14（Asia/Shanghai），仅方案修订。详细契约在本地忽略目录 `.codeartsdoer/plans/aiw14-workbench-library-search/ui-reference-r4.md`，此文件保存关键决策，不能代替缺失的完整计划直接开工。

两种展示共享同一业务数据：活动/任务浏览用头像彩色短卡；活动内部与发布者后台用紧凑任务分工表。原活动/任务胶囊、桌面三列与左1右2继续使用；点击活动后，右侧应直接呈现任务表。

| 要素 | 当前方案要求 |
|---|---|
| 卡片 | 图2整卡柔和色底、约8px圆角、约32px头像、16px常规标题、紧凑元信息；横向短矩形，不按正方形实现 |
| 表格 | 图1细网格、紧凑行、低饱和状态标签、头像姓名和浅蓝选中行；任务/所属活动/状态/执行成员/开始/截止/完成/受权操作 |
| 活动切换 | 活动详情与后台都有切换路径；保留来源scope/authz、深链、后退；A晚到不得覆盖B；后台独立任务仍可访问 |
| 用户身份 | 活动卡显示负责人；任务卡显示approved执行成员，支持多人；未分配与发布者身份分清；同user_id跨页面一致 |
| 状态与权限 | 提交不等于已验收；子任务完成不自动验收父级；活动负责人不自动拥有所有任务的指派/验收权 |

源码核对到的缺口：User没有头像字段；ActivityTaskNode只有姓名字符串，表格缺稳定成员ID、开始时间和逐人状态等只读信息。首批用基于user_id的本地默认头像，复用已受权任务集合或补最小投影；不新增用户目录、外部头像请求或图片上传功能。

图片文案只是参考，不将P0/P1、工时、评论数、附件数、blocked、字段配置/生成表单/分享视图自动变成需求。当前志愿时长不能解释成预计工时。

浅色卡底真实像素采样：`#FEC6B7`、`#B7E0FE`、`#F1BADF`、`#BFF2FD`，来源为用户图2四点读取。实现映射现有主题令牌并单独验深色，不修改颜色检查基线/白名单。

实施归属仍为AIW-14，新增T14-R4-01～05：核对读模型/头像身份→彩色短卡→活动共用表/切换→后台复用→视觉与行为验收。当前正在开发，接手时先协调写集。本轮未接管stage30源码。

验收入口：R-26/29/30，AC-20/24/25/26。重点包括多人/未分配/同名不同用户、活动A/B乱序、展开不重复、跨组织与角色授权、后台独立任务、写入成功/失败摘要同步、1440/390模拟与深浅主题的参考图对照。
