四、本地 Playwright CLI 与工具执行纪律

当前浏览器验证优先复用已经获准安装的本地 Playwright CLI，
以及 work/aiw07/runner/ 中已有的脚本和验证方式。

先检查现有脚本、依赖、浏览器、进程和执行结果。
不重复安装另一套依赖，不默认切回 Playwright MCP。
不把 work/ 中的本地工具依赖纳入项目运行时依赖或 Git 提交。

使用当前交接和实际进程对应的服务与数据库。
端口、数据库路径、测试账号和页面地址都要现场核对，
不照抄旧聊天中的端口、PID 或数据库。

一次执行一个有明确范围和超时的验证脚本。
等待脚本退出，读取：
- 退出码；
- 失败步骤；
- 控制台和网络错误；
- 实际页面状态；
- 截图或录屏；
再决定下一步。

同一脚本仍在运行时，不重复启动第二份。
同一工具调用未返回前，不再次派发相同调用。

脚本内部不得包含：
- 无限导航；
- 无限登录；
- 无界重试；
- 没有退出条件的页面轮询；
- 失败后不断重复相同操作的循环。

导航后等待明确的 URL、元素或业务状态。
不使用反复 goto、navigate 或刷新来等待页面加载。
对登录、提交、验收等写操作，
结果不明时先查询或观察，不能直接重复执行。

失败后先根据实际日志、输入和页面状态定位原因。
没有新的原因判断、修复或可验证假设，
不得重复执行完全相同的失败脚本。

连续两次修复失败后，先补日志、复现或输入输出观测，
停止继续猜测。
第三次仍失败，整理目标、证据、已试方案与结果，
停止该问题的无效重试并报告。

如果使用 MCP 或其他交互工具，
同样遵循“一次调用、一次结果判断”：
- 每次工具提交只包含一个浏览器调用；
- 读取返回结果后再决定下一动作；
- 不在同一条回复中重复提交相同 tool_call；
- navigate、click、fill、evaluate、snapshot 都适用。

出现 doom loop、工具禁用或平台保护时，
立即停止受影响的调用。
不修改保护阈值、不清内部限制状态，
不通过别名或其他客户端绕过禁用。
本地 CLI 的使用以用户已有授权为依据，
不能作为绕过平台保护的手段。

正常恢复后只执行一次最小只读检查。
仍失败就保存原始错误和断点，
不反复重启服务或连续尝试相同操作。

工具故障、测试脚本错误和应用缺陷分别判断。
未复现的页面现象不直接判定为业务代码缺陷。
