# Prompt 迭代记录

> **用途**：记录业务 Agent（提炼助手 / 审核助手）以及 Agent Team 启动指令的版本演进，格式为
> **badcase（现象）→ 修改（改了什么）→ 效果（如何验证）**。Prompt 质量是官方评分点，本文件是直接证据。
>
> **口径说明**：下表只记录**已在代码/文档中固化、可核验**的演进项。运行期试跑发现的 badcase 需由技术负责人在真实迭代后补录，
> 未发生的条目一律不填（宁可留空，不可编造）。业务 Agent Prompt 正文位于 `backend/app/agents/prompts.py`。

| P-001 | 提炼助手 `EXTRACTOR_SYSTEM_PROMPT` | 只返回字段值时，前端无法定位「这段原文对应哪个字段」，彩色文字块与数据面板无法同色联动 | 在输出 JSON Schema 中**追加 `spans` 数组**（记录原文片段与所属字段），Prompt 其余措辞、换行、标点一律不改写 | `frontend/src/components/VoiceComposer/BlockText.vue` 可按 span 染色；颜色取自 `utils/colorPool.ts`，与 `FieldPanel.vue` 同色 |
| P-002 | 提炼助手 Prompt 渲染 | Prompt 正文含大量 JSON 花括号，用 `str.format` / f-string 渲染会抛 `KeyError: 'title'` 一类异常 | 改为 `str.replace("{CURRENT_TIME}", ...)` 单点注入当前时间，并在 `prompts.py` 文件头写明**禁止使用 `format` / f-string** | `render_extractor_prompt()` 可稳定渲染；相对时间（"下周三下午三点"）能按当前时间解析 |
| P-003 | 提炼助手 · 风格剥离 | 用户说「措辞严谨一点」时，该指令易被写进 `details` / `notes`，污染任务正文 | 增加独立规则：与任务内容无关、只关乎表达方式的要求必须剥离到 `style_prompt`，**不得混入 `details`/`notes`** | 前端将 `style_prompt` 单独渲染为「风格要求」标签；审核助手按该要求润色，返回 `polished` 供一键替换 |
| P-004 | 提炼助手 · 动态字段 | 标准字段之外的要求（如「信息学院要带电脑」「着正装」）会被丢弃 | 增加规则：此类要求以键值对放入 `extra_tags`，键用简短中文，值用用户原话具体内容 | `frontend/src/views/PublishPage.vue` 面板支持增删任意键值对行；`colorForField` 对 `extra_tags.` 前缀统一着色 |
| P-005 | 提炼助手 · **增量解析**（第二轮 R12） | badcase：AI 首次解析后输入栏被锁定，用户想补「人数修改为 6 人」只能去右侧改字段；若要求用户重述全句，历史字段与更正记录容易被模型丢掉 | 新增 `mode="incremental"` 入口：请求携带 `{text: 本次追加文本, base_draft: 当前草稿}`；Prompt **仅在末尾追加**「增量 + 纯值」提示段——只解析本次文本涉及的字段，返回与 `base_draft` 合并后的完整草稿，并给出字段级 `changes`（`old_value` 取 `base_draft` 的值） | 契约验收 R12-AC5：`base_draft.quota=3` + 「人数修改为 6 人」⇒ `draft.quota=6` 且 `changes` 含 `{op:"set", field:"quota", old_value:3, new_value:6, source:"ai"}`；T3 落地后由 `tests/backend/test_agent_incremental.py` 断言（**效果的真实命令输出待 B 段补写**） |
| P-006 | 提炼 / 审核助手 · **纯值约束**（第二轮 R13） | badcase：模型把「建议改为 14:00」整句放进 `new_value`，前端落值后 `time` 字段变成「建议改为 14:00」，数据被建议语污染，且采纳后无可追溯记录 | 在输出 Schema 与 Prompt 中**强制** `new_value` 只含**纯值**（`14:00` / `教四` / `5` / `搬桌椅`），禁止「建议 / 改为 / 请 / 或 / 可 / 推荐」等建议语；建议语句只进 `ambiguities[].question` 与 `changes[].reason`（仅展示）；后端 `is_pure_value()` 校验，不合格即**丢弃该 change**（宁缺勿污染） | 契约验收 R13-AC2/AC4/AC5：不合格 suggestion ⇒ `changes` 为空、`ambiguities` 保留、采纳按钮置灰；回归红线断言字段值不含 `AI建议` / `改为` / `用户：` 前缀（**真实断言输出待 B 段补写**） |
| P-007 | 提炼助手 · **顺序增量链式**（第三轮 B7） | badcase：语音流式解析**每片都重发累计全文**（从开口到当前），越说请求越大、延迟逐片递增，模型重复解析前句并出现重复字段/重复文字块（用户原话：「每片都重发累计全文，越说越慢、还重复解析前句」） | 语音流式改为**顺序增量链式**：第 N 片只发 `{text: 本片 chunk, base_draft: 当前草稿, mode:"incremental"}`，**不发累计原文**；上一片返回并合并进草稿后才发下一片（串行、禁并发乱序）；`finishStreaming` 只补发最后一片 | 验收方向：链路第 N 片的请求体**不含**前 N-1 片原文；字段值与前句不重复；单片耗时随句子增长不递增。**真实结果（T5 实测）**：monkeypatch 截获 payload **恰为三键**（`本次新增片段` / `当前已合并草稿` / `是否最终`），`backend/app` **32 个 `.py`** 中「累计原文」**0 命中**；HTTP 三片链式 —— 片 2 `changes=['location']`（不含 `time`）、片 3 `changes=['quota','extra_tags.工作内容']`（不含 `time`/`location`），`extra_tags` 不重复；空尾片 `changes==[]` 且不清空已有字段；`test_agent_incremental.py` **358 断言 PASS** |
| P-008 | 审核 / 生成助手 · **润色与介绍只出建议条**（第三轮 B10） | badcase：说「帮我生成一个温柔的活动介绍」没有生成介绍；且审核助手的润色结果被**自动塞进字段**，字段值出现整段带建议语的文案（用户原话：「没有生成介绍；且润色不能被自动塞进字段」） | `polished` 与「活动介绍」类生成结果改为**独立建议条**下发，**永不自动落值**：不进入 `draft` 任何字段、也不进入 `changes`（延续 D5 纯值红线）；前端只渲染建议条 + 「采纳」按钮，点击后才写值并生成 `ai_applied` 追溯块；风格要求 `style_prompt` 改为**叠加拼接**、不判语义矛盾 | 验收方向：生成介绍指令有可见产出；未点「采纳」时 8 个字段与 `extra_tags` 均不含建议语整句；多次风格要求并存不覆盖。**真实结果（T5 实测）**：`polished.details` 为完整介绍（≥20 字、含标题），但**入参 `draft.details` 仍为 `None`**，介绍**不进入** `changes`（`details`/`notes` 均无）⇒「只出建议条、永不自动落值」成立；`join_style_prompt` **8 组**断言 PASS（`温柔一点、措辞严谨一点` 重复补充不叠加）；`needs_intro` **6 组**断言 PASS；`test_agent_incremental.py` 358 / `test_agent_mock.py` **229** 断言全 PASS |
| P-009 | 语音收尾 · **onend 驱动 + 保帧不丢 + `stopping` 守卫**（第四轮 C5） | badcase：用户**读完最后一个字立刻停止**时，末尾几个字**丢失或重复**，且停止后**不再**自动产出审核/润色建议（用户原话：「说完最后一个字立刻停止时，最后几个字会丢 / 重复，且停止后不再自动出审核建议」）。根因：`stop()` 在 **800ms** 后调用 `resetLocalBuffer()` **清空本地缓冲**，而 `recognition.stop()` 是**异步**的——浏览器随后补发的**最后一帧**在缓冲已空时被当作**新内容**重新切片，与**已发送的尾片重叠**（重叠即重复，未落入缓冲的末段即丢字）；尾片发送与审核触发解耦，尾片未闭合则不出建议 | 收尾改为 **onend 驱动 + 保帧不丢**：`stop()` **只**置收尾窗口 `stopping = true` 并挂 **3s 兜底**（`FORCE_FINALIZE_MS`），**不**自己发尾片、**不**清缓冲；`onend` 到达后延迟 `FINAL_DELAY_MS`，把 `pendingText`（尚未发送部分）**全量**作为尾片发送（**晚到帧已入缓冲，因此一并发出去**）；`stopping` 期间识别帧**照常写入缓冲**（保帧），但 `scheduleSlices()` 守卫 `if (stopping) return` **不零散发片**；缓冲只在**尾片成功发送后**由 drain 清一次；尾片成功后仍自动进入审核，**两个 agent 顺序不变**（提炼助手 → 审核助手）。**v1「收尾锁丢弃晚到帧」被否决**：用户的复现条件正是「读完最后一个字马上停止」，锁窗口内到达的恰是最后几个字，丢帧等于丢有效内容、直接失守「末批必达」；且「丢弃」无法区分晚到帧是新内容还是上一批残留，一刀切必然误伤 | 验收方向：「读完立刻停」情形下**末批必达**（最后几个字不丢）、**不重复**（同一段话不重复发送）、**两个 agent 顺序不变**、停止后**仍自动出审核建议**；`stopping` 期间无 `is_final=false` 的零散片发出；缓冲不在尾片前置清空。**真实结果（T6 首轮实测）**：`frontend/.t1-voice-check` 场景 **A/B/C 共 25 断言 PASS**（A 14 / B 7 / C 4，`=== 结果：全部通过 ===`）——A8「尾片恰好一次（count=1）」、A9「尾片内容=晚到文字」、A10「总发送=片 1+尾片，无重复 partial」、A12「顺序 `applyStream(9) → finishStreaming(11) → onAllChunksSent(12)`」、A14「review 通知恰一次」；B4/B5「`onend` 丢失后 3s 兜底同样尾片恰好一次且含晚到文字」、B7「兜底路径仍触发一次 review」；C1~C3「空尾片不产生额外请求、仍结束 streaming 并通知一次」。静态契约 `check_contracts.py` ㉑ PASS（`stop()` 体内**无** `resetLocalBuffer(` / `enqueue(` / `FINAL_DELAY_MS`；`scheduleSlices()` 首条 `if (stopping) return`；`onend` 两分支互斥；`FINAL_DELAY_MS` 仍为 800、切片 5 常量未改）。真机麦克风三保证按 `O-D4-4` 记 **DEFERRED（M27/M28，不计 PASS）**；最终结论见 `tests/security/ACCEPTANCE.md` |

| P-010 | 语音续接 · **续接去重链必须保留（`dedupTail` 仅在新建会话时清空）+ `trimRestartOverlap` 重叠裁剪**（第五轮 D2/D3） | badcase：用户**没有点停止**、正常连续说话，同一句在草稿里出现两遍，第二遍常带前导逗号（`资源时长两小时` → `资源，时长两小时`）。根因：Edge 的 `continuous` 并非真无限，停顿后静默触发 `onend` 并 `start({ keepSession: true })` 续接；而 `start()` 里的 **`dedupTail = ''` 写在 `if/else` 之外无条件执行**——`keepSession` 只保住了后端 `parse_session`，却把前端去重链清空了。`dedupTail` 是 `applyInterim` / `applyFinal` 的去重锚点（相等 ⇒ 丢弃；新帧以旧帧为前缀 ⇒ `replaceTail` 覆盖尾部；否则追加），锚点一空，「覆盖」退化为「`fullText += transcript` 追加」，续接实例回填重吐的前缀帧被整段追加；重复片段随后被切片发给后端，而第三轮 **B7** 的顺序增量链式只发「本片 + 当前草稿」，后端把它当「本次新增片段」合并，模型照抄进字段与 `spans` ⇒ **草稿里真的存了两份**（不是渲染错觉）。第二遍带前导逗号，正是重吐回退边界落在上一句标点上的指纹 | 1) **`dedupTail` 的清空只保留在「新建会话」分支**，`keepSession` 续接**保留**去重链（续接不再断链）；2) `utils/voiceSlicer.ts` 新增纯函数 **`trimRestartOverlap(prevTail, transcript)`**：取本地已收文本的尾部一段与前文比对，裁掉续接首帧里与前文重叠的前缀（含前导标点），并仅在续接后的**前若干帧**窗口内生效、新建会话不进入该窗口；3) `commitStoppedSession()` 首行加**幂等守卫**（已结算或无可结算文本即返回），作为防御性冗余；4) 切片 5 常量（`PUNCT_THRESHOLD` / `MAX_CHUNK_CHARS` / `SILENCE_CUT_MS` / `FINAL_DELAY_MS` / `LIVE_MAX_REFRESH_MS`）与 C5 的 `stopping` / `onend` 结算时序**一律不动** | 验收方向：不点停止、句间停顿超 800ms 让 Edge 自动续接 ≥1 次时，同一句**恰好一遍**、第二遍**无前导标点**；连续不停顿说完（不触发续接）时行为不变；C5 三保证（末批必达 / 不重复 / 两 agent 顺序不变）不回退。**真实结果（T4 终验实测）**：`check_contracts.py` **25/0**（㉒ D1 / ㉓ D2 / ㉔ D3 / ㉕ D4 全 PASS；㉓ 实测「`keepSession` 分支 `dedupTail` **0 处**、`else` 分支 **1 处**」）；`e2e_headless.py` **52/0**（D1：`Host: test.hn.takin.cc` → **200**、`Host: evil.example.com` → **403**；D2：分支结构与窗口赋值；D3：**仅追加分支调用**裁剪、`replaceTail` **0 命中**；D4：首条有效语句 `if (!stopping) return`）；`check_voice_slicer.cjs` **21/0**（含 `trimRestartOverlap` **8 组**：`("明天下午两点","明天下午两点去操场") → "去操场"`、`("一二三四五","三四五六七八") → "六七八"`）；桩测 `.t1-voice-check` **25/25**（尾片 `count=1`、无重复 partial、顺序 `applyStream → finishStreaming → onAllChunksSent`）。**误裁边界如实记录**：单字重叠不裁（`("资源时长两小时","资源，时长两小时")` 原样返回），真实重复语句若落在 3 帧续接窗口内**可能被裁一遍**（R3，已知边界）；真机麦克风与真实公网域名按 **M29~M31 记 DEFERRED**。最终结论见 `tests/security/ACCEPTANCE.md` |

## 三、写记录的规范

1. **必须带输入样例**：只写"效果不好"没有价值，要写清触发 badcase 的原话（脱敏后）。
2. **必须写改动点**：是加了一条规则、改了一个字段名，还是调整了输出 Schema；能贴 diff 就贴 diff。
3. **必须写验证结果**：重跑同一输入的结果，或指向 `debug/` 中的排错记录、`screenshots/` 中的截图。
4. **Prompt 正文唯一来源**：以 `backend/app/agents/prompts.py` 为准；本文件只记录"为什么改"，正文不在此重复粘贴，避免两份不一致。
