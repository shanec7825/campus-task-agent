## 执行顺序

1. 先核对服务健康、目标 URL、数据库/模型模式与现有进程。端口与库以当前阶段交接为准，不得混入历史演示库或未确认的代理目标。2026-11-14 后续口径：8000 = `work/aiw07/demo2.db`（主流程），8010 = `work/aiw07/demo3.db`（零额度），8001 已停止。
2. 当前页已打开时，第一步只调用一次 `browser_snapshot`。禁止先重复导航 /admin、/login。
3. 每次助手工具提交只包含一个浏览器调用；等待返回并读完结果后才能决定下一调用。同一动作未返回前不再次派发。
4. 导航结果已经含快照时直接读该快照。页面已是目标 URL 不重复 navigate；需要等待页面状态时观察目标元素/只读快照，不用导航当轮询或刷新。
5. 点击/填表基于最新快照引用。先一步动作，再观察实际 URL/页面状态；不要在一次脚本内循环尝试登录或导航。
6. 超时/未知结果不能直接重发写操作或导航。先一次只读观察确认是否已完成；再次观察也失败就保存错误并停该浏览器用例。
7. 出现 doom loop、工具禁用或平台保护：立即停止该会话的浏览器调用；不改保护阈值、不清内部状态、不用别名/其他客户端绕过。保存断点，让平台正常恢复后再继续。
8. 设置里的 MCP 正常重启只恢复服务连接，不承诺解除当前对话的保护。恢复后只做一次只读快照确认工具可用，再继续单步操作；仍禁用则交由平台支持处理，不持续重启。
